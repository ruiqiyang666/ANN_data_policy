# model_v2：Booth2 电极维护预警

本目录包含第二版的训练数据、代码、12个候选的权重、冻结测试结果和离线报告。最终按验证集选择 **GRU（16隐单元）**，历史测试 **2/3次达到提前至少20分钟**。目前适合作为实验结果与后续现场验证的起点，尚未稳定达到全部事件提前20分钟，也没有接通现场接口。

## 先看结果，不需要安装软件

**打开 [model_v2_results.html](model_v2_results.html)**。这是可单独转发的HTML：图表、案例数据、README及两张结果CSV均已嵌入，不依赖你的电脑路径、Python或本地服务器。接收人下载文件后，用Edge、Chrome等浏览器打开即可。

在GitHub看到HTML源码属于正常现象，请下载文件后打开；聊天软件的内置预览可能不执行交互脚本。需要同事查看模型代码或继续训练时，发送整个 `model_v2` 目录。

页面按以下顺序看：

1. **评估结论**：当前选中哪个模型，达标几次、漏掉几次。
2. **三条测试案例**：依次切换10/28、11/1、11/10，对照失败开始T、T−20截止线和实际报警。
3. **模型比较、全部报警、训练曲线**：零误报不代表没有漏报，损失下降也不等于现场预警达标。

页面后续电压线是**后来实际测到的电压**，不是模型预测出的未来电压曲线。切换候选只改变查看对象，不会改变冻结选型。

## 真实测试表现

**T＝最终连续失败序列中，第一件失败产品开始加工的时刻。首次有效报警必须在T−20分钟或更早。** T不是第二件失败结束、停喷开始或实际换枪时刻。

| 测试事件 | 失败开始T | 最晚达标报警时间T−20 | 实际发出的报警 | 结果 |
|---|---|---|---|---|
| 10/28 · T010 | 08:25:39 | 08:05:39 | 07:42:50，提前42分49秒 | 达标，比要求早22分49秒 |
| 11/1 · T011 | 13:33:02 | 13:13:02 | 13:36:40，已经失败3分38秒 | 未提前预警，计漏报；事件后报警另外保留 |
| 11/10 · T012 | 13:28:30 | 13:08:30 | 13:02:00，提前26分30秒 | 达标，比要求早6分30秒 |

- 测试达标 **2/3**，另一次没有有效提前预警；不能把66.7%叫作逐点分类准确率。
- 测试覆盖 **91.33个有效产品生产小时**：可判误报0条，另有2条事件后报警。不能把事件后报警删除后声称所有报警都有效。
- 验证集是 **1/2达标、1次不足20分钟、4条误报／52.78个生产小时**。选择GRU遵守验证误报预算；零测试误报不能代表其他时段或未来现场同样零误报。
- 这版输出风险评分和报警；没有声称已经学会精确剩余分钟或经济意义上的最优换枪时间。达标后计算的“多提前多久”只覆盖达标事件，不能叫全体剩余寿命MAE。

完整明细见 [event_results.csv](artifacts/event_results.csv) 和 [alarm_results.csv](artifacts/alarm_results.csv)。其中11/1在事件表中的 `first_alarm` 为空，表示没有可计分的提前报警；13:36:40记录在报警表中，标记为 `post_event=True`，两张表没有矛盾。

## 数据范围、划分与输入

历史范围为已提供的 **2026/9/12—11/14 Booth2数据**。按完整电极周期分组；同一周期和重叠历史窗口不跨集合，不随机拆CSV行。

| 集合 | 周期 | 可监督电压末期事件 | 实际测试／评估原点 |
|---|---|---:|---:|
| 训练 | L000—L004，5个周期 | 5次 | 31,976，拟合时按分钟抽取其中7,612个可监督原点 |
| 验证 | L005—L007，3个周期 | 2次 | 18,043 |
| 测试 | L008—L013，6个周期 | 3次 | 31,216 |

原点是一条历史预测机会，不是一件产品或一次独立故障。11/6预防性更换保留为正常／自然终点未观察到的删失记录，不算自然失效正例；11/9损坏更换没有可确认的产品低压终点，不填造失效时间。11/10已按最新现场确认更新证据和时间。

10/28、11/1曾参与第一版验证，11/10也已查看。本轮属于扩大历史留出评估；3次事件不足以证明稳定泛化，后续需要新增完整现场周期。

沿用核对后的完整产品分段：正转—短暂换向—反转属于同一件产品，不能在换向低速处切开。按完整加工均值判定：电压<51V；送料<9.1或>11.1g/min；罐压<100或>250mbar，保留现场纠正和不确定数据屏蔽。真实凌晨加工不因时间排除。

模型只读取过去60分钟中当时可获得的9个传感器，以及从过去数据计算的活动料斗、60秒电压均值和波动。保留缺失掩码和数据年龄，预处理只拟合训练集。完整产品最终均值、failure、未来维护、事后枪龄和周期编号均不作为数值输入；周期键只用于历史／告警重置。

送料连续失败没有足够正例，罐压连续失败仅有少量训练证据。本包的电极维护成绩不能当作另外两类预警已验证有效的证据。

## 如何核验、重新训练

以下为**Windows／PowerShell、Python 3.13、CPU**的已用环境。不需要复制原作者的虚拟环境。先进入你下载或克隆得到的 `model_v2` 文件夹，再执行：

```powershell
py -3.13 -m venv ..\.venv-model-v2
$modelPython = (Resolve-Path '..\.venv-model-v2\Scripts\python.exe').Path
& $modelPython -m pip install torch==2.9.1 --index-url https://download.pytorch.org/whl/cpu
& $modelPython -m pip install -r requirements.txt
```

**只核验已有结果，不训练、不调参：**

```powershell
& $modelPython -X utf8 src/evaluate.py --verify-only
& $modelPython -X utf8 -m unittest discover -s tests -v
& $modelPython -X utf8 src/replay.py
```

交付复核：冻结代码、数据、权重和测试台账哈希一致；26项检查通过；31,216个测试原点独立逐点回放通过，最大评分差约1.43e-6，4条实际报警时刻一致。回放核验的是部署推理与保存台账一致，不能代替真实现场效果评估。

**重新训练：**

```powershell
& $modelPython -X utf8 reproduce.py --name colleague_01
```

输出到 `runs/colleague_01/`，保留当前交付结果。新实验复制包内已准备数据，不依赖桌面 `JJ` 路径。初始训练、有限验证扩展、封存、测试、回放、报告会依次执行；训练日志在新实验的 `artifacts/`，完成后打开其 `model_v2_results.html`。

不要删除已评估目录的保护文件来调测试成绩；同一历史数据重训不是新增独立测试。若要重新执行原始数据处理，仍需要完整本地源文件、11/17时间核对表及传感器时钟文件；这些不属于直接重训的必要输入。

仅重新打出单文件报告：

```powershell
& $modelPython -X utf8 src/report.py --share-only
```

## 部署边界与数据流

本次训练在本机CPU完成，没有第二版服务器训练或真实现场接通记录。

计划数据流：**现场 → 应用服务器采集 → 数据服务器留存 → ANN服务器推理／告警 → 应用展示**。同一交换机提供网络连接条件，仍需接入协议、权限、字段时间／质量码、延迟及换枪重置信号适配。

`src/inference.py`中的 `StreamingPredictor.push(...)`接收已经准备好的加工原点和真实过去60秒统计，并不是可直接连接PLC的完整服务。历史回放也沿用了离线确认的加工资格，不能等同于原始异步PLC全链路上线。

线上保留Gun_ID、Gun_Hours、Ignitions的未来接入能力；历史缺少这些字段时，不能从事后登记回填作输入。本批冻结清单包含Windows路径分隔符，交付核验按Windows完成；在Linux ANN服务器上直接使用这批冻结权重前需先适配清单路径并复核。详见 [部署说明](docs/deployment.md)。
