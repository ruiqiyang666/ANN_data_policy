# 本机配置与算法调研

调研日期：2026年11月4日。硬件与Python环境为本机实测；算法信息来自当日读取的官方仓库、模型卡、论文和文档。模型选择与资源预算是本项目建议，不是已完成训练的结果。

**结论：本机可以承担首轮数据整理、简单基线、小型TCN及小型PatchTST训练，建议先在本机做。暂不需要因硬件不足转服务器。主路线采用自监督表示学习、未来300秒事件预测和低复杂度生存模型；预训练大模型作为有限的对照实验。**

本轮只做硬件查询、Python/CUDA元数据检查、联网调研和文档更新。没有安装依赖、下载模型、执行数据处理、运行训练、进行GPU算子基准或连接服务器。

## 2. 真正需要匹配的是标签条件

现有主设备原始数据约540万行、28参数；已有产品标注覆盖9月12日至10月23日，按公司明确修订为58件异常、28段异常。自然寿命事件的起始清单只有5次低压后换新推定，尚需利用已有数据区分早期不稳定与持续退化。大量正常数据、131条采样不足记录及其他未人工标注数据都有利用价值，但不会变成新增的独立自然失效案例。

因此模型要同时做到：利用大量运行历史学习表示；正确处理提前换枪导致的未观察到自然失效；不把密集窗口当成大量独立故障；把当前异常、未来300秒异常及自然失效寿命分开监督。公司不再补标不是本轮工作的等待项。

## 3. 算法比较与取舍

下面同时列出较新的候选和适合本数据的成熟基线；“更新”不等于在本设备上更准确。公开预测基准的排名也不能替代本项目的失效验证。

| 方法 | 已核实能力 | 本项目用法与判断 |
| --- | --- | --- |
| 小型因果TCN + 自监督预训练 | TS2Vec等工作展示了利用无标注时序学习表示的方法；需自行适配因果推理和28通道 | **首轮主方案**。学习过去窗口的遮挡重建/表示一致性，再训练事件分支；网络控制在100万参数以内。称为本项目适配方案，不冒充原版TS2Vec复现。[TS2Vec论文](https://arxiv.org/abs/2106.10466)、[作者仓库](https://github.com/zhihanyue/ts2vec) |
| 小型PatchTST | 分块Transformer、通道共享、自监督及线性探测/微调 | **结构对照**。使用小网络，并补上跨通道融合；保留绝对电压等物理量。不能仅靠逐窗归一化抹掉退化基线。[官方仓库](https://github.com/yuqinie98/PatchTST)、[论文](https://arxiv.org/abs/2211.14730) |
| 正则化AFT / XGBoost AFT | AFT可表达事件时间；XGBoost AFT明确支持精确、右删失和区间标签 | **寿命必做基线**。优先低维、强正则模型；XGBoost AFT仅作浅树对照，不用几次事件拟合复杂树群。[LogNormal AFT](https://lifelines.readthedocs.io/en/latest/fitters/regression/LogNormalAFTFitter.html)、[XGBoost AFT](https://xgboost.readthedocs.io/en/stable/tutorials/aft_survival_analysis.html) |
| 离散时间风险模型（LogisticHazard思路） | 用分段事件风险和生存似然学习到事件的时间 | **未来300秒主输出**。10个30秒区间同时提供风险与条件ETA；类型另作多标签。区间事件、部分观察和重复事件的处理需要本项目实现，不能假定库默认全部支持。[pycox官方说明](https://github.com/havakv/pycox) |
| Chronos-2 / Chronos-2-Small | 多变量及协变量预测；官方列出120M标准版、28M小版；模型卡标Apache-2.0 | **较新模型的优先对照**，先评估小版。只用历史电压/送料及28参数历史协变量生成辅助预测特征，检验对事件预警是否有增益；不直接把未来数值分位数当作失效概率或RUL。[官方仓库](https://github.com/amazon-science/chronos-forecasting)、[小版模型卡](https://huggingface.co/autogluon/chronos-2-small) |
| MOMENT | 面向多种时序任务，包含表示、分类和异常检测；可做线性探测 | **可选冻结表示对照**。其当前异常得分不等于未来5分钟事件概率，仍需目标任务监督；先冻结骨干，避免直接全量微调。[ICML论文](https://proceedings.mlr.press/v235/goswami24a.html)、[官方仓库](https://github.com/moment-timeseries-foundation-model/moment) |
| TiRex-2（2026） | xLSTM系列多变量零样本预测，支持历史及已知未来协变量 | **研究储备**。官方公开版每次重算传入历史；增量流式接口、微调及分类/回归支持列在PRO版，不能默认开源版已提供这些能力。[官方说明](https://nx-ai.github.io/tirex-2/introduction/)、[官方仓库](https://github.com/NX-AI/tirex-2) |
| TimesFM 3.0 / 2.5 | 官方2026年8月发布3.0，原生多变量；2.5为200M且有LoRA示例 | **3.0不选作本地公司看板部署主线**：下载权重限制非商业、非生产使用；2.5权重仍为Apache-2.0，可作备选。此取舍来自实际发布说明，不是推测许可风险。[官方仓库及许可说明](https://github.com/google-research/timesfm) |

Chronos、TiRex、TimesFM首先解决未来数值预测。它们没有在当前数据上学会“电极什么时候自然失效”。将预测电压跌破阈值直接换算成自然寿命，会混入早期不稳定、工况变化和产品均值判定的差异。分位预测也没有自动给出跨整个300秒窗口的联合事件概率。首轮主线直接训练事件目标，基础模型仅比较是否能改善这些目标。

本项目没有可靠已知的未来传感器值。使用支持协变量的模型时，28参数默认都只能作为过去信息；不能把测试段实测未来电流、压力、送料作为已知未来协变量。压力保持输入/异常类别，不增加未来压力数值输出或独立预测损失。

## 4. 推荐的训练顺序

### 第一步：统一标签和冻结分区

用同一规则补齐8月15日至9月11日产品及事件；应用公司已给出的压力修订、实际采样点均值和低压说明，保留旧编号映射。5次换新推定保留证据等级，正常提前更换作为右删失；身份或失效状态不明的样本不强造寿命标签。

| 用途 | 预定日期 | 约束 |
| --- | --- | --- |
| 训练与自监督预训练 | 8月15日—9月29日 | 归一化、特征选择、表示预训练均仅使用此分区 |
| 模型选择 | 10月4日—10月7日 | 早停、有限方案比较 |
| 校准 | 10月8日—10月9日 | 有有效标签时校准异常概率/门槛；不得默认可校准寿命区间 |
| 最终测试 | 10月10日—10月23日 | 冻结后一次评价；不得用于预训练、微调或调阈值 |

沿用[日期与周期隔离规则](数据划分与首轮训练流程.md)，跨界周期不得拆进不同分区。当前5次推定按日期分布是训练3、选择1、校准0、测试1；还不是周期隔离后的最终数。首轮不能承诺获得独立验证的90%寿命区间。若整理后仍只有这些事件，寿命结果须逐事件报告，校准状态明确为证据不足，不能反复调参直到单个测试事件表现好。

### 第二步：先建立简单基线

异常基线采用相同历史统计的正则化分类/离散风险模型，另选一个浅树模型作对照。寿命先做低复杂度AFT：比较截距模型与少量预先限定的物理特征，尺度参数先设为全局；不把数百维特征全部送进只有几次事件的回归。XGBoost AFT可作后续对照，但不把拟合更复杂当成必然改进。

### 第三步：在训练历史上自监督预训练小型编码器

输入最近120秒×28参数及质量信息，保留5/15/60分钟因果统计。预训练目标是对过去窗口内人为遮挡的已观测数据进行重建，原始缺失点不当重建真值。可从15%的短连续遮挡起步；绝对电压、送料、压力单位和跨通道关系必须保留，不做会改变故障含义的任意幅值缩放或时间打乱。

首轮采用32通道、5个因果残差块的小型TCN。预训练输入及监督都来自训练分区；内部监测也取训练分区内隔离的时间块。预训练最多20轮；这是初始预算，不是已验证收敛设置。与不预训练的同结构TCN比较，不能只凭重建误差下降判断故障预测更好。

### 第四步：训练异常分支，再固定表示训练寿命分支

- 未来300秒：10个30秒风险区间，计算总体异常概率；条件ETA与风险来自同一时间分布，异常类型保留电压/送料/压力多标签。未观察满窗口的记录按可观察前缀处理。
- 当前异常：采用独立状态输出，与未来新事件区分。同一事件附近样本控制总权重，评价按事件统计。
- 自然寿命：先冻结编码器、在训练数据内压缩表示，仅为AFT保留极少数特征；不让几次失效事件直接训练整个大网络。小型寿命头输出剩余带电时间分布，剩余件数另用计数监督。
- 自然失效点、失效区间和提前更换观察分别采用事件、区间和删失损失；换枪发生时刻不替换自然失效时刻。规则推定单独标记，做包含/排除可疑事件的敏感性检查。
- 健康分没有独立真值时采用明确说明的工程指标或不可用状态，不附加凭空生成的健康标签。

### 第五步：只做有限对照

| 顺序 | 实验 | 用途 |
| --- | --- | --- |
| A | 简单异常模型 + 正则化AFT | 建立可解释的最低比较标准 |
| B0 | 小TCN，不预训练；相同任务头 | 判断时序网络是否有用 |
| B1 | 相同TCN + 自监督预训练；相同任务头 | **主候选**，检验未标注历史的收益 |
| C | 小型PatchTST，2—3层、64维、4头；相同监督 | 比较分块注意力与TCN；总参数预算不超过100万 |
| D | Chronos-2-Small辅助电压/送料预测特征 + 同一事件模型 | 较新基础模型的有限对照；先冻结，只有选择集显示明确收益才考虑微调 |

优先完成A、B0、B1；C、D逐个加入。60秒窗口仅在主结构确定后作一个窗口对照，不展开架构×窗口×多种基础模型的大规模搜索。MOMENT、TiRex-2和TimesFM 2.5记录为储备，不全部排入首轮训练。

## 5. 本机配置与资源预算

| 项目 | 首轮设置或目标 |
| --- | --- |
| 运行环境 | 本目录内独立环境；优先复现已识别GPU的Python 3.13/PyTorch 2.11 cu128组合；第三方有兼容问题时另建3.12环境 |

540万行×28通道若仅存float32值，约0.563 GiB，尚未含时间、掩码、标签和容器开销。若把每一秒的120秒窗口全部复制，单输入就约67.62 GiB；每10秒取窗也约6.76 GiB。因此使用按天数据块或内存映射和窗口索引，训练时按批读取，不能提前展开全部重叠窗口。128×120×28的单批原始float32值约1.64 MiB；实际显存还包括激活、梯度、优化器及库工作空间。

首轮执行时先测少量训练步的峰值内存和吞吐量，再确定整轮耗时。预热20步、测量100步可作为起点，正式统计需包含数据加载和CUDA同步。本轮没有运行这些步骤，不给出伪精确的“几分钟训完”承诺。

## 6. 什么情况下使用服务器

本机目前不是硬件不足。以下情况才建议切换：

- 实际测量表明所选模型在缩小批量、使用混合精度和按需取窗后仍无法留出足够显存。
- 长时间训练影响日常使用或笔记本持续性能不合适，需要稳定后台运行。
- 较大基础模型的多变量长上下文微调确实改善验证效果，且本机实测吞吐/显存不合适。

服务器仍使用`dev@100.104.199.22`，不假定服务器一定比本机强。先用[服务器配置核查命令](服务器配置核查命令.md)取得实际GPU、空闲显存、内存和磁盘。对于较重的基础模型实验，24GB及以上空闲显存、64GB内存是方便安排的建议目标，不是所有训练的硬性最低要求。

代码目录为`/home/dev/Zhang/Phase2`，数据只读引用`/home/dev/Zhang/private/Real-time Data`，新模型/缓存/日志写`/home/dev/Zhang/private/results/real28_training_20261104/<run_id>`。运行时不占用或重启现有panel服务。按用户偏好提供服务器命令由用户执行；目前没有连接服务器。

## 7. 第一版交付如何判断

交付包括自然剩余带电时间/件数及模型范围、未来300秒异常概率/类型/条件ETA、当前异常、任务状态和解释，取消60秒后压力预测。按相同日期和周期隔离比较基线、TCN与候选，报告事件召回、每百运行小时误报、首次失败前提前量、逐周期寿命误差和适用范围。

现有测试时段仅1次低压后换新推定时，不用大量相邻窗口计算虚假的高置信度，也不宣称完成普遍可靠的自然寿命验证。自监督和基础模型能改善表示学习；能否改善本设备预测需要实际比较，增加算力本身不会增加独立失效证据。
